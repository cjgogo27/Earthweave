# 架构与边界

Earthweave 将“世界”定义为按地理位置组织、可追溯来源的视觉记录网络。地球是索引，地点是入口，媒体是证据；全景和未来的三维模型提供不同等级的空间体验。

## 当前数据流

```text
手机 / 相机导出文件 / 电脑 / 受支持的 HTTPS 媒体直链
        ↓
网页选择地点、填写元数据、选择媒体类型
        ↓
匿名浏览器会话 → 服务端验证 → R2 媒体对象
                        └→ D1 媒体与地点记录
        ↓
交互地球 → 地点列表 → 平面查看 / 全景查看 → 可选 WebXR
        ↓
作者删除 / 浏览者举报
```

页面使用 React，应用路由运行于 Vinext 与 Cloudflare Worker。Three.js 负责浏览器三维显示；D1 保存可查询元数据，R2 保存二进制文件。不要将媒体内容塞进数据库文本列，也不要把浏览器本地存储当作多人共享存储。

应用不要求 GPT / ChatGPT 登录，匿名访客可浏览与贡献。站点托管访问策略需允许公众直达；应用自身使用浏览器会话管理记录归属，与托管平台账户无关。匿名贡献并不等于完成了生产级社区治理。

## 网络导入与来源

`POST /api/import` 接收 JSON：

```json
{
  "url": "https://允许的媒体域名/实际文件",
  "title": "地点名称",
  "description": "拍摄内容说明",
  "lat": 0,
  "lng": 0,
  "kind": "panorama",
  "device": "来源采集设备",
  "license": "CC-BY-4.0",
  "rightsConfirmed": true,
  "sourceAttribution": "原作者与出处"
}
```

示例中的 URL 与坐标只是字段说明，不能直接用于真实导入。用户必须填写实际拍摄坐标、媒体类型和适用许可；`rightsConfirmed` 只接受布尔值 `true` 作为确认。成功响应为 HTTP 201 与 `{ "scene": ... }`。导入与普通上传共用内容校验、配额、去重和持久化逻辑。

服务器只请求准确域名 `dl.polyhaven.org`、`upload.wikimedia.org`、`images.unsplash.com`、`videos.pexels.com`，要求 HTTPS 默认端口，拒绝 URL 中的用户名或密码。下载限时 20 秒，限制实际读取量为 32 MiB；最多跟随 3 次重定向，每跳重新验证允许域名。请求不会转发访问者的身份头或 Cookie。

其他公共 HTTPS 来源走浏览器 CORS 获取路径；来源不允许跨域读取时提示用户下载后上传。该回退不扩大服务器的来源白名单。此功能面向直接媒体文件，不解析网页，不下载视频平台页面，不自动推断拍摄地点。

`sourceUrl` 与 `sourceAttribution` 写入 D1。`author` / `authorId` 表示本站上传者，不能覆盖或冒充外部原作者。文件复制到 R2 后仍保留原始来源及许可；来源域名获允许不代表所有资源已自动获得使用授权。

## 双语界面

`lib/i18n.tsx` 提供中文 / English 上下文与浏览器语言偏好。用户内容不自动翻译。全景与地球的提示保留中英文本，在渲染时选择语言；Canvas 辅助标签单独更新，语言切换不销毁三维场景或中断 VR 会话。

## 媒体语义

| 类型 | 可提供的体验 | 不应作出的承诺 |
| --- | --- | --- |
| 普通照片 | 在地点查看一张实拍图 | 自动恢复图外和被遮挡的真实景物 |
| 普通视频 | 播放拍摄时的视觉路径 | 任意选择拍摄者未经过的新视角 |
| 360° 照片 / 视频 | 在拍摄点转头环视；适配头显显示 | 具有真实平移视差的自由行走 |
| 三维网格 / 高斯模型，后续 | 在有效重建区域改变观察位置 | 对未采集区域、尺度或几何正确性的保证 |

全景采用等距柱状投影。2:1 尺寸是格式线索，不是内容证明。重建质量还依赖采集覆盖、重叠、曝光、运动物体和相机姿态。AI 补全必须单独标识，不可覆盖实拍记录的来源。

## 身份与写入边界

首次 `GET /api/scenes` 在缺少有效会话时创建匿名身份，响应返回 `{ user: { id, name }, ... }`。Cookie 使用 32 随机字节编码成的 64 位十六进制令牌；D1 的 `browser_sessions` 只保存 SHA-256 令牌哈希、独立 UUID 用户 ID、创建时间和到期时间，不保存原始令牌。

HTTPS 下 Cookie 名为 `__Host-earthweave_session`，本地 HTTP 为 `earthweave_session`，使用 `HttpOnly`、`SameSite=Lax`、`Path=/`，HTTPS 还设置 `Secure`。最长有效期为 365 天。写入接口同时验证同源请求与有效会话；缺失会话时返回 401，客户端可刷新列表以建立新会话。接口不信任客户端自报的作者 ID，也不依赖 Sites 注入的身份头。

清除 Cookie、过期或换浏览器会失去旧记录的管理权限，不会让旧记录被自动删除。当前没有账号恢复、可下载管理密钥或跨设备所有权同步。本机收藏与语言偏好另存于 localStorage。浏览器令牌是管理能力，不应写入日志、公开 Issue 或 Git。

迁移 `0002` 只新增匿名会话表。早期 GPT 作者记录保留旧 `author_id`，仍能被查看，但不会自动赋予匿名访客删除权。任何所有权恢复或转移应由维护者基于可信证据单独处理，不能按显示名猜测。

客户端元数据与文件均不可信。服务端应检查允许的媒体类型、32 MB 文件上限、坐标范围、字段长度与资源归属。R2 对象键应由服务端产生，避免将上传文件名当成存储路径。媒体响应应使用明确的 Content-Type。

举报是待处理问题记录，不代表平台已经执行人工审核、自动打码或事实核查。当前有每个匿名身份每小时 20 条记录的基础检查，并以文件哈希检查同一作者的已发布重复内容。访客可以重新建立浏览器身份，因此这不是全站防滥用方案。扩大公共使用前仍需要审核角色、处理队列、申诉与删除追踪，以及网关级配额和运营机制。

R2 和 D1 之间没有跨服务事务。当前写数据库失败会尝试删除刚写入的对象；清理自身仍可能失败，删除也需要考虑部分失败与重试。生产扩展应增加幂等请求标识、清理任务和可观测状态。

## WebXR 与设备

网页先提供普通屏幕浏览，再检测是否存在兼容的沉浸式 VR 会话能力。启动沉浸会话需要用户操作；不可假设所有浏览器、手机或头显均支持。部署应使用 HTTPS。详情见 [WebXR Device API](https://developer.mozilla.org/en-US/docs/Web/API/WebXR_Device_API)。

全景纹理越大，解码内存与显存成本越高。除单文件 32 MB 限制外，当前图片校验限制单边 16,384 像素及总量 8,000 万像素；这仍不保证所有头显能顺畅解码。扩大使用范围前需要多分辨率切片、视频转码、按设备选择清晰度，以及实际头显帧率与舒适度测试。首次测试使用 [VR 实机清单](vr-test.md)，未经测试的视频不能因图片流程通过而标记为兼容。

当前上传协议面向文件，不绑定某一手机型号。相机、无人机和扫描设备可以导出支持的格式后使用同一入口；这些设备的原生直连、实时流与厂商 SDK 尚未实现。

## 部署选择

### 独立 Cloudflare，开源默认路径

仓库跟踪带占位 D1 ID 的 `wrangler.json`，使用 `DB` 与 `BUCKET` 绑定。`npm run db:migrate` 应用本地迁移；`npm run dev` 启动开发服务；`npm run build` 构建；`npm run deploy` 校验真实 D1 UUID、重新构建、应用远程迁移并部署 Worker。首次部署需在自己的 Cloudflare 账户创建 D1/R2 并更新配置。应用的匿名身份机制在此路径上直接运行，无须 OpenAI 密钥或 ChatGPT 登录，步骤见 [部署指南](deployment.md)。

### 可选 Sites 托管

源码保留部分 starter 的 Sites 辅助能力，用于兼容已有托管流程。它不参与应用的登录或作者身份判断。Sites 的访问策略属于托管层，公开站点需配置公开访问；不要把某个站点的私密凭据、数据库导出或上传对象放入开源仓库。

### 传统服务器 / 私有机房

需要 Node 服务入口或其他后端适配层；D1 改用 SQLite/PostgreSQL，R2 改用 S3 兼容对象存储或经过权限控制的文件服务，同时适配匿名会话持久化与 Cookie。随后补充备份、迁移、TLS、日志和任务处理。地理查询扩大后可考虑 PostGIS。此路线为后续工程方案，当前仓库不包含完成的传统服务器适配。GitHub Pages 的静态托管不能承载这些 API 与存储职责。

## 后续扩展

1. **采集质量与社区维护**：采集指引、模糊与重复检查、作者修订、地点时间线、审核处理。先让记录可靠，再扩大全球覆盖。
2. **Panoramax 互通，未实现**：通过 API 导入可用的地理照片与来源元数据，保留实例、原始 ID、许可、作者和获取时间；满足条件后再考虑加入联邦目录。不得把外部素材复制为无来源的自有内容。
3. **GPU 重建队列，未实现**：视频抽帧 → 素材质检 → COLMAP 相机估计 → Nerfstudio/Splatfacto → 验证与压缩 → R2 结果 → 浏览器查看。计算运行在独立 GPU 工作节点，Cloudflare Worker 只协调状态。
4. **空间配准与分块，未实现**：为每个重建区域保存位置、尺度、姿态与精度；地球坐标和局部场景坐标转换明确；按空间块加载，避免把全世界资产同时放进显存。
5. **音频与触觉，未实现**：增加独立的感知资源层，保留时间、位置和设备信息。音频应获得独立授权；触觉依赖具体硬件协议，不是添加一个上传字段即可完成。

“真实世界视觉记录”“计算重建结果”“生成式补全”始终保留不同来源与置信度，避免视觉效果被误认为真实测量。
